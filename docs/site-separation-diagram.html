CastFolio Site Separation Architecture

3-Model Cross Review Complete | Opus (Architecture) + Sonnet (Security) + Haiku (UX/DX)

Before vs After

BEFORE: Single Domain

castfolio.wideget.net

  • Partner B2B landing + Client token pages on same domain
  • Client sees "Partner SaaS" when visiting homepage
  • /submit/[token] shares domain with /app/dashboard
  • /create wizard - unclear who it's for
  • One branding tone for two completely different users

AFTER: Split Domains

castfolio.kr + partner.castfolio.kr

  • Each user group has dedicated domain & branding
  • Client sees warm, friendly landing on castfolio.kr
  • Token pages isolated on client domain
  • /create clearly lives on client site as self-service tool
  • Single codebase, single deployment (Vercel)

Middleware Domain Routing

// middleware.ts - hostname-based route isolation
const hostname = request.headers.get("host")

if (hostname.includes("partner.")) {
  // Site A: block client routes, serve partner routes
  if (/submit|review|delivered|quote/) → redirect("castfolio.kr" + path)
  if (path === "/") → rewrite("/(partner)/page")
} else if (hostname.includes("castfolio.kr")) {
  // Site B: block partner routes, serve client routes
  if (/app|admin|login/) → redirect("partner.castfolio.kr" + path)
  if (path === "/") → rewrite("/(client)/page")
} else {
  // Unknown hostname → default deny (Security: Sonnet #7)
  return NextResponse.json({error: "forbidden"}, {status: 403})
}

// /p/[slug] → shared, accessible from both domains
// Canonical: always castfolio.kr/p/[slug] (SEO: Opus #4)

3-Model Review Findings (Consolidated)

CRITICAL (Must fix before split)

CRITICAL Opus Supabase cookie domain conflict — cookies set on partner.* invisible to castfolio.kr
CRITICAL Opus NEXT_PUBLIC_APP_URL hardcoded — token email links will point to wrong domain
CRITICAL Sonnet Auth cookies httpOnly: false — JS can read auth tokens (XSS risk)
CRITICAL Sonnet Middleware auth check is cookie-name-only — forgeable, no signature verification

HIGH (Fix during split)

HIGH Opus Route group layout collision — root layout shared, can't vary <html> per domain
HIGH Opus /p/[slug] SEO — responds on both domains, needs canonical + 301 redirect
HIGH Opus + Haiku /create wizard ambiguous — partner tool or client self-service?
HIGH Sonnet OAuth callback open redirect via //evil.com trick
HIGH Sonnet In-memory rate limiter bypassed on serverless (per-instance)
HIGH Sonnet /delivered/[token] leaks partner PII (name, email, phone)
HIGH Sonnet No security headers (CSP, X-Frame-Options, etc.) on either domain
HIGH Haiku Client landing missing trust signals, turnaround time estimate, "before/after"

MEDIUM

MEDIUM Opus 4-domain redirect chain (wideget.net → castfolio.kr) needs documentation
MEDIUM Opus Legacy route redirect map complexity (/dashboard/*, /public/*)
MEDIUM Sonnet Hostname rewrite has no default-deny fallback
MEDIUM Sonnet CORS not configured on /api/public/* for cross-domain
MEDIUM Haiku Route group split increases middleware complexity vs flat routes

LOW

LOW Opus Single deployment = single failure domain for both sites
LOW Opus Local dev needs NEXT_PUBLIC_DEV_DOMAIN_MODE env var
LOW Sonnet Locale cookie missing SameSite + Secure flags
LOW Haiku Branding consistency — /p/[slug] needs neutral tone for both contexts
